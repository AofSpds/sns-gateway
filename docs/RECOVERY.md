# 복구 안내

현재 소스·날짜·삭제 계약은 LIFECYCLE.md를 따른다. 아래 작업은 앱이 관리하는 데이터에 한하며 원본이나 SNS 게시물을 자동 삭제하지 않는다.

## native 모듈 없음

Expo Go가 아니라 native bridge가 포함된 빌드가 필요하다. JS 번들 성공은 native 설치가 아니다. 개발 환경·빌드 식별자·안전한 오류 코드만 확인하고 개인 키를 채팅에 보내지 않는다.

## 소스 권한·조회 실패

사진 없음과 다르다. 설정에서 권한을 확인하고 다시 연결한다. 새 연결은 새 baseline이므로 기존 사진을 일괄 가져오지 않는다. iPhone 제한 권한이나 기기에 없는 iCloud 사진은 직접 사진 가져오기 경로를 사용한다. 서버 다운로드를 대신 켜지 않는다.

## 날짜 또는 버전 충돌

날짜를 다시 열어 현재 버전을 확인한다. 이전 내용을 덮어쓰지 않는다. 미저장 문구가 있으면 저장 후 날짜를 옮긴다. 닫힌 날짜는 먼저 다시 열고, 정리된 사본은 '사용 가능한 사본만 남기고 저장'으로 명시적 새 버전을 만든다.

## 공유 후 결과 미확인

이미 SNS에 게시됐을 수 있다. 자동 재공유하지 말고 수신 SNS를 확인한 다음 사용자 완료/취소를 표시한다. 중단된 REQUESTED는 다음 DB 열기 때 미확인으로 복구한다. OS callback과 원격 게시 성공은 다르다.

## 삭제·초기화 실패

삭제 journal이 남으면 다음 상태 새로고침에서 재개한다. 파일이 없어짐을 확인한 뒤에만 삭제 완료 상태를 기록한다. 초기화가 미완료이면 다른 작업보다 이를 먼저 재개하고 원래 누른 작업을 자동 재실행하지 않는다. 미확인 공유는 삭제/초기화 전에 사용자 확인이 필요하다.

## DB 오류

v1/v2는 추가형 v3 migration으로 이관한다. 알 수 없는 버전·FK 오류·이관 실패는 기존 데이터를 보존하고 오류로 남긴다. DB 파일을 임의 삭제해 성공시키지 않는다. 정상 초기화 기능도 사용자 확인을 거쳐야 한다.

## 알림이 늦거나 지난 날짜임

권한·채널·집중 모드·전원을 확인한다. Android는 inexact이며 정시 전달을 보장하지 않는다. 표시 날짜를 확인하고 원하는 날짜를 직접 연다. iOS 반복 알림의 전달일은 원 예정일과 다를 수 있다. 알림 설정은 사진 마감09:00와 별개다.
